# 按图：基础单价与像素阶梯

管理入口：模型定价 → 添加/编辑模型 → 按图。

第一块配置美元/张的基础单价；第二块可添加一组像素规则，包含多个阶梯。“其他”规则类型暂不支持。

像素数等于请求宽 × 高。请求使用 `size: "1024x1024"`，或同时提供数值型 `width`、`height`；有 `size` 时优先使用它。启用像素规则后，缺少明确尺寸、`auto`、`1K` / `2K` 等标签会在调用上游前返回参数错误，不从响应或图片文件中推断尺寸。未启用像素规则时，所有图片使用基础单价。

1K 档的总像素是 1,048,576，`1024x1024` 与 `2048x512` 命中同档。每档下限不包含、上限包含；最后一档无上限。阶梯上限必须为递增的正整数，倍率必须是大于零的有限数值，允许大于 1 表示加价。基础单价允许为零。

同一请求的所有图片使用同一请求尺寸。每张图片命中一个档位，不分段累加像素费用。

```json
{
  "example-image-model": {
    "base_price": 0.1,
    "pixel_tiers": [
      { "max_pixels": 1048576, "multiplier": 0.5 },
      { "max_pixels": 4194304, "multiplier": 0.8 },
      { "max_pixels": null, "multiplier": 1 }
    ]
  }
}
```

以上是 `ImagePrice` 配置项的存储格式。旧版规则数组继续读取和执行，界面提供显式替换入口，不自动将旧版绝对价格换算成像素倍率。

预扣费用使用请求数量；OpenAI 图片结算优先采用有效的 `usage.generated_images`，缺失时使用 `data` 数组长度。流式请求使用完成事件计数或已报告的 usage；客户端中断时保留已有的计数保护。非法上游数量会记录警告，不允许成为无界计费乘数。报告零张时新按图配置的最终费用为零。

计算公式：图片数量 × 基础单价 × 像素倍率 × 分组倍率；最终额度使用统一 quota 换算与饱和审计。

账单 `other.image_billing` 保存请求时的价格快照，包括版本、基础单价、倍率、单价、请求尺寸、宽高、像素数、命中档位上下限、数量及来源、分组倍率、额度换算单位和实际扣除额度。账单详情按该快照显示计算过程，修改当前定价不改变旧账单的计费依据。
